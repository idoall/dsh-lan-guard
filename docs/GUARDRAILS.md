## 3. 网络行为边界

### 可以做

- `npm install` / `npm view` / `npm search` 等包管理操作；
- 查询 npm registry、GitHub API、上游文档；
- 绑定 `127.0.0.1` 的本地测试服务。

### 不可以做

| 禁止 | 原因 |
| --- | --- |
| 让监听地址对外可达而门禁未生效 | 等于把用户的机器暴露在局域网上 |
| 实现任何公网隧道 / IM Bot / 端口转发 | `docs/SPEC.md` 的非目标 |
| 绑定 `0.0.0.0` 做测试而不加门禁 | 测试也不允许出现无门禁的对外监听 |
| 对外部地址发起请求（除包管理与查文档） | 可预期性与隐私 |

### 例外：验证反代时的临时监听

验证「局域网可达」这件事本身需要绑 `0.0.0.0`。允许，但必须同时满足：

1. 门禁代码已经生效并经过测试；
2. 绑定的端口是专用测试端口（不要占用 DSH 的 3080）；
3. 验证完成后**立即关闭**监听；
4. 在汇报里说明「曾短暂监听 0.0.0.0:<port>，已关闭」。

## 4. 数据与凭据边界

### 绝不可进入仓库、日志、汇报、截图的内容

- 门禁密码明文与密码哈希；
- 门禁会话令牌（session token）；
- DSH 的 cookie 签名 secret（`client-connection/browser-session` 的 `payload.secret`）；
- DSH 的 launch token（`?token=` 值）；
- 任何证书私钥（`ca-key.pem`、`server-key.pem`）；
- 用户 `~/.dsh/.credentials.yaml` 的内容。

### 允许的处理方式

- 在测试里使用**固定的假值**（如 `test-secret-not-real`），不得使用真实凭据；
- 需要读取真实 secret 才能实现的功能（例如自签 cookie 方案），**在运行时读取、只在内存中持有**，不得落盘、不得打印；
- 日志里对上述字段做脱敏（只打印长度或前 4 位）。

### 证书与密钥的落盘位置

- 生成物写入用户 DSH home 下的插件私有目录（具体路径在 `docs/SPEC.md` 定稿）；
- **不写入本仓库**；
- 私钥文件权限收紧（参考 `docs/RESEARCH.md` §5.1 的做法）。

## 5. 职责矩阵

`R` = 负责执行；`A` = 最终批准；`C` = 需咨询；`I` = 需知会。

| 事项 | AI | 用户 |
| --- | --- | --- |
| 按阶段写实现 | **R** | A |
| 写测试 / 跑类型检查 | **R** | I |
| 本机（`127.0.0.1`）验证 | **R** | I |
| 手机 / 平板实机验证 | C | **R** |
| 重启 dsh | **禁止** | **R** |
| 决定密码策略、证书主体名 | C | **A/R** |
| 引入新依赖 | C | **A** |
| 修改约束文档（`AGENTS.md`、`GUARDRAILS.md`、`SPEC.md`、`PLAN.md`） | C | **A** |
| 阶段推进确认 | C | **A** |
| 发布（npm / tag / Release） | **禁止**（未获授权时） | **A/R** |
| 建远程仓库、推送 | **禁止**（未获授权时） | **A/R** |
| 升级 DSH 基线版本 | C | **A** |

**关键点**：AI 永远不是 `A`（批准者）。凡是涉及对外影响、不可逆、或改变规则的，批准权在用户。

## 7. 功能边界（做什么 / 不做什么）

### 做

- 在 `0.0.0.0:<自定义端口>` 上提供反向代理，转发到 `127.0.0.1:<DSH 端口>`；
- HTTP 与 WebSocket（`upgrade`）双向转发；
- 请求头改写（Host / Origin → loopback）与上游会话 cookie 注入；
- 密码门禁：访问密码 + 独立管理密码、免密链接令牌、会话、IP 失败锁定；
- **向官方内容型 seat 注册设置 UI**：`settings.section`（设置分区，F6 的做法）、`shell.overlay`（全帧浮层）；
- 管理端点用 `connection.requestRejection()` 复用 DSH 原生栅栏保护；
- **默认开启**的自签 TLS（CA + 按网卡 IP 签发的叶证书；可关闭，关闭时设置页必须提示影响）；
- 多网卡选择、地址展示，以及设置页二维码（P3，必做）。

### 不做

- ❌ 不替换或修改官方 Web UI 的**布局**——`sidebar` / `rightbar` / `shell.leading` 等布局型 slot，以及 `panelInfo` 等 layout 根 hook，一律不动；
  （**注意区分**：向 `settings.section` / `shell.overlay` 这类**内容型 / 追加型** seat 注册内容**是允许的**，那是 F6 设置页的唯一实现方式。）
- ❌ 不改 DSH 的 `host` 绑定、不改 DSH 源码；
- ❌ 不做公网隧道（Cloudflare / cpolar / FRP / Tailscale）；
- ❌ 不做 IM Bot（微信 / QQ / 飞书 / Telegram）；
- ❌ 不做手机专属界面（抽屉式侧栏、全屏会话等）；
- ❌ 不做设备配对 / mDNS 发现（P4 之前）；做与不做由用户在 P4 决定；
- ❌ 不做多用户 / 账号体系（单密码门禁足够）；
- ❌ 不做 DSH 业务 API 的解析、改写或缓存（透明转发即可）。

## 8. 违反红线的处理

如果发现自己（或上一个会话）已经违反了某条红线：

1. **立即停止**当前工作；
2. **不要自行扩大改动**去"补偿"；
3. 在汇报中如实说明：违反了哪条、改动了什么、当前状态；
4. 等用户指示是否回滚、如何回滚；
5. 不要隐瞒或轻描淡写——这是最严重的漂移形式。
