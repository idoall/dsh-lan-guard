<h3 id="cn-v0.1.1">中文</h3>

### 版本对应

本版本仍针对 **DeepSeek Harness `0.1.7-rc.1`**，声明范围不变（`>=0.1.7-rc.1 <0.2.0`）。**没有任何代码改动**，不需要迁移。

### 为什么必须适配

**这次不需要适配**：DSH 侧没有变化，本版本也没有功能改动。之所以仍然发一版，是因为 **npm 页面显示的是「已发布 tarball 里的 README」**——0.1.0 打包时用的是实施前的规划稿 README，只有重新发布才能把新版文档送到 npm 页面上。

### 改了什么

- **README 重写为中英双语用户文档**（`README.md` / `README.zh.md`，各 147 行），结构对齐同系列插件：徽章 + 语言互链 + 锚点导航 + 「能力 / 安装 / 使用 / 兼容性（含插件版本 ↔ DSH 版本对应表）/ 配置（完整键表与默认值）/ 排障 / 安全边界 / 卸载 / 开发」；
- 措辞由「计划提供的能力」改为**已发布状态**的准确描述（已发布到 npm、手机真机验证通过）；
- 补上原先缺失的用户内容：`dsh plugin --profile web add dsh-lan-guard` 安装、手机侧完整使用步骤、兼容性版本对应表、完整配置键表、6 个真实排障场景、安全边界（本机物理免锁、远程默认只读、共享密码的边界、无公网隧道）、卸载步骤；
- 其余一切不变：代理、门禁、自签 TLS、设备配对、设置页、端口顺延、可选 mDNS 均与 0.1.0 相同。

### 谁受影响

- **只有文档受影响**：已安装 0.1.0 的用户不需要升级，功能完全一致；
- 想在新项目里参考文档、或直接看 npm 页面的人：这一版让 npm 页面与仓库文档一致；
- 使用 `@latest` 安装的新用户会拿到 0.1.1（内容与 0.1.0 相同，仅文档更新）。

### 兼容性与升级

- 与 DSH `0.1.7-rc.1` 配套；`peerDependencies` 与 `engines` 未变；
- **从 0.1.0 升级无需任何操作**：配置、密钥、设备配对记录（`dataDir` 下的 `secrets.json` / `devices.json` / CA）全部沿用，不迁移、不失效；
- 回滚到 0.1.0 同样安全（数据格式未变）。

### 限制

- 与 0.1.0 相同的限制，逐条列在 README 的「限制 / 安全边界」一节：自签 CA 需每台设备信任一次；mDNS 默认关闭且手机浏览器基本用不上（**二维码才是主路径**）；远程默认只读；局域网明文 HTTP 需显式确认风险；访问密码是共享的（吊销设备只让该设备的身份 cookie 立即失效）；不提供任何公网隧道 / IM Bot / 端口转发。

<h3 id="en-v0.1.1">English</h3>

### Version correspondence

Still built for **DeepSeek Harness `0.1.7-rc.1`** with the same declared range (`>=0.1.7-rc.1 <0.2.0`). **No code changed**, so there is nothing to migrate.

### Why this release exists

**No adaptation was needed**: nothing changed on the DSH side, and this release carries no functional change. It exists because **npm serves the README from the published tarball** — `0.1.0` was packed with the pre-implementation planning README, so only a new publish can put the rewritten documentation on the npm page.

### What changed

- **Both READMEs rewritten as user-facing documentation** (`README.md` / `README.zh.md`, 147 lines each), structured like the sibling plugins: badges + language switcher + anchor nav + Features / Install / Usage / Compatibility (with a plugin-version ↔ DSH-version table) / Configuration (full key table with defaults) / Troubleshooting / Security boundary / Uninstall / Development;
- Wording moved from "planned capabilities" to accurate **shipped** descriptions (published on npm, verified end-to-end on a real phone);
- Added the previously missing user content: `dsh plugin --profile web add dsh-lan-guard`, the full phone-side walkthrough, the compatibility table, the complete configuration key table, six real troubleshooting scenarios, the security boundary (loopback physically unlocked, remote read-only by default, the shared-password boundary, no public tunnels) and uninstall steps;
- Everything else is unchanged: proxy, gate, self-signed TLS, device pairing, settings UI, port fallback and optional mDNS are identical to 0.1.0.

### Who is affected

- **Documentation only**: users on 0.1.0 do not need to upgrade — the behaviour is identical;
- People reading the npm page or the repo docs get a consistent, complete description;
- New installs via `@latest` get 0.1.1 (same code as 0.1.0, documentation updated).

### Compatibility and upgrading

- Matches DSH `0.1.7-rc.1`; `peerDependencies` and `engines` are unchanged;
- **Upgrading from 0.1.0 needs no action**: configuration, secrets and paired devices (`secrets.json` / `devices.json` / the CA under `dataDir`) carry over — no migration, nothing is invalidated;
- Rolling back to 0.1.0 is equally safe (the on-disk format did not change).

### Limitations

- The same limitations as 0.1.0, itemised in the README's Limitations / Security boundary section: the self-signed CA must be trusted once per device; mDNS is off by default and phone browsers rarely use it (**the QR code is the reliable path**); remote access is read-only by default; LAN plain HTTP requires an explicit risk acknowledgement; the access password is shared (revoking a device only invalidates that device's identity cookie); no public tunnels, IM bots or port forwarding.
