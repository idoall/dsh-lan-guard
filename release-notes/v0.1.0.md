<h3 id="cn-v0.1.0">中文</h3>

### 版本对应

本版本针对 **DeepSeek Harness `0.1.7-rc.1`** 开发与验证，声明范围为 `>=0.1.7-rc.1 <0.2.0`。已在 `0.1.7-rc.1` 上完成真机端到端验证：手机扫码 → 信任自签 CA → 密码门禁 → 进入官方 Web UI → 收发消息（WebSocket 长连接正常）。

### 为什么做这个插件

DSH 的 Web 界面只监听 `127.0.0.1`，手机、平板等设备无法直接使用。官方明确拒绝把监听地址改成 `0.0.0.0`，而公网隧道类方案又超出「局域网内用一下」的需求。

dsh-lan-guard 的做法是：**不改动 DSH 自身的绑定，也不改动官方 UI**，而是在另一个端口上开一个带门禁的反向代理，把官方 Web 界面安全地开放给同一局域网内的设备。

### 改了什么（首个版本）

- **带门禁的反向代理**：HTTP 与 WebSocket 全量转发，Host/Origin 改写，逐跳头剥离；上游不可达时返回 502；
- **访问门禁**：PBKDF2-SHA256（600,000 次迭代）双密码（访问密码 + 管理密码）、`dsh_` 免密令牌、持久访客会话、按 IP 锁定、CSRF 校验；
- **默认自签 HTTPS**：自动生成 `DSH LAN Guard CA` 并按网卡 IP 签发叶证书，CA 身份跨重启不变，私钥 600；
- **本机物理免锁 / 远程按策略**：本机直连（回环）免锁可写；远程可设 `local_only`（默认，只读）/ `password_unlock`（需解锁）/ `open`；代理为每个转发请求打上不可伪造的来源标记；
- **设备身份与配对**：手机首次通过门禁时显示配对页命名设备，服务端下发 HttpOnly 设备身份 cookie，桌面「已授权设备」可查看（名称/创建/最近使用/来源 IP）并逐个吊销，吊销后该设备立即被拒；
- **设置页**：挂载在官方设置页内的「局域网访问」分区，含扫码访问（唯一二维码 + 地址）、安全认证、已授权设备、连接与证书四个 tab；排版全部使用官方 `--dsw-font-*` / 颜色 token，主按钮用官方品牌蓝；
- **端口**：默认 `3081`（DSH 端口 + 1），被占用时自动顺延（最多再试 10 个），设置页可改并带可用性检查；
- **可选 mDNS**：默认关闭，开启后广播 `_dsh-lan-guard._tcp`。

### 谁受影响

- 想在**手机 / 平板上使用 DSH** 的人：这是本插件的主要用途；
- 在意「不把 DSH 暴露到公网」的人：本插件只面向局域网，且默认带 TLS 与门禁；
- **不需要**本插件的人：完全不受影响——不安装即无任何行为变化，安装后默认也只监听回环地址，必须显式配置才会对局域网开放。

### 兼容性与升级

- 与 DSH `0.1.7-rc.1` 配套；`peerDependencies` 声明 `@deepseek-ai/dsh-host-webserver`、`@deepseek-ai/dsh-client-connection` 为 `>=0.1.7-rc.1 <0.2.0`；
- 复用官方 `settings.section` 与 `shell.overlay` 两个**追加型** seat，不替换任何官方布局；
- 配置在插件 Config 与 profile patch 中，升级插件不改变既有配置；
- 卸载后不会在 DSH 侧留下任何改动（DSH 自身配置从未被修改）。

### 限制

- **自签 CA 需要每台设备手动信任一次**（否则浏览器会警告）；CA 指纹在设置页可复制；
- **mDNS 默认关闭**，且即便开启，iOS Safari / Android Chrome 在实践中也不会为任意网页解析 `.local` 名字——**手机上的可靠路径仍是二维码**；
- **远程默认只读**（`local_only`）：手机能用 DSH，但不能修改插件设置；需要时在桌面切换策略；
- **局域网明文 HTTP 需要显式确认**（`tls.allowInsecureLan`，默认关闭）——开启后门禁密码不再加密，请自行评估风险；
- **访问密码是共享的**：吊销设备保证该设备的身份 cookie 立即失效，但换浏览器用密码重新登录仍可再次配对；要做到「同一台机器永久拉黑」需要设备指纹或每设备独立令牌，本版本未提供；
- 本插件只面向**局域网**，不提供任何公网隧道 / IM Bot / 端口转发能力（刻意不做）。

<h3 id="en-v0.1.0">English</h3>

### Version correspondence

Built and verified against **DeepSeek Harness `0.1.7-rc.1`**, declared range `>=0.1.7-rc.1 <0.2.0`. End-to-end verification on `0.1.7-rc.1` was done on a real phone: scan the QR code → trust the self-signed CA → pass the password gate → use the official Web UI → send and receive messages (WebSocket mux stays connected).

### Why this plugin exists

DSH's Web UI listens on `127.0.0.1` only, so phones and tablets cannot use it directly. DSH deliberately refuses to bind `0.0.0.0`, and public tunnels are overkill for "I just want to use it on my LAN".

dsh-lan-guard keeps **DSH's own binding untouched and the official UI unmodified**, and instead runs a gated reverse proxy on a second port that safely exposes the official Web UI to devices on the same LAN.

### What changed (first release)

- **Gated reverse proxy**: full HTTP and WebSocket forwarding, Host/Origin rewriting, hop-by-hop header stripping, 502 when the upstream is unreachable;
- **Access gate**: PBKDF2-SHA256 (600,000 iterations), two passwords (access + admin), `dsh_` passwordless tokens, persistent visitor sessions, per-IP lockout, CSRF checks;
- **Self-signed HTTPS by default**: generates a `DSH LAN Guard CA`, issues a leaf certificate for the selected NIC address, keeps the CA identity stable across restarts, private keys mode 600;
- **Local machine is physically unlocked, remote follows policy**: loopback access needs no unlock and may write; remote can be `local_only` (default, read-only), `password_unlock` (needs an unlock) or `open`; the proxy stamps every forwarded request with an unforgeable origin marker;
- **Device identity and pairing**: a phone that passes the gate for the first time is asked to name itself, receives an HttpOnly device cookie, appears in "已授权设备" (name / created / last used / source IP) and can be revoked individually — a revoked device is refused immediately;
- **Settings UI**: a "局域网访问" section inside the official settings page with four tabs (QR access, authentication, authorised devices, connection & certificates); typography and colours use the official `--dsw-font-*` / colour tokens, primary buttons use the official brand blue;
- **Port**: defaults to `3081` (DSH's port + 1), automatically walks up to 10 ports when taken, editable in the settings page with an availability check;
- **Optional mDNS**: off by default; when enabled it advertises `_dsh-lan-guard._tcp`.

### Who is affected

- People who want to **use DSH from a phone or tablet** — the main use case;
- People who care about **not exposing DSH to the public internet** — this plugin is LAN-only, with TLS and a gate on by default;
- People who do **not** need it: installing nothing changes nothing. Even installed, it listens on loopback until explicitly configured to face the LAN.

### Compatibility and upgrading

- Matches DSH `0.1.7-rc.1`; `peerDependencies` declare `@deepseek-ai/dsh-host-webserver` and `@deepseek-ai/dsh-client-connection` as `>=0.1.7-rc.1 <0.2.0`;
- Uses only the official **additive** seats `settings.section` and `shell.overlay`; no official layout is replaced;
- Configuration lives in the plugin Config and the profile patch; upgrading does not disturb existing configuration;
- Uninstalling leaves nothing behind on the DSH side (DSH's own configuration was never modified).

### Limitations

- **The self-signed CA must be trusted once per device**, otherwise browsers warn; the fingerprint is copyable from the settings page;
- **mDNS is off by default**, and even when enabled iOS Safari / Android Chrome do not resolve `.local` names for arbitrary web pages in practice — **the QR code remains the reliable path on a phone**;
- **Remote access is read-only by default** (`local_only`): a phone can use DSH but cannot change plugin settings; switch the policy on the desktop when needed;
- **Plain HTTP on the LAN requires explicit acknowledgement** (`tls.allowInsecureLan`, off by default) — the gate password is no longer encrypted, evaluate the risk yourself;
- **The access password is shared**: revoking a device invalidates that device's identity cookie immediately, but re-pairing with the password from another browser is still possible; a permanent per-machine ban would need device fingerprinting or per-device tokens, which this release does not provide;
- This plugin is **LAN-only** and deliberately provides no public tunnels, IM bots or port forwarding.
