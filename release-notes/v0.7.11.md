<h3 id="cn-v0.7.11">v0.7.11：兼容 DSH 0.2.2-rc.3</h3>

兼容 DeepSeek Harness `0.2.2-rc.3`（并含 `0.2.2-rc.2`）；支持范围 `>=0.1.7-rc.1 <0.3.0` 不变。

- 兼容声明新增 `0.2.2-rc.2`、`0.2.2-rc.3`；上界 `<0.3.0` 已覆盖，不需要放宽范围或版本豁免。开发依赖 `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` 同步到 `0.2.2-rc.3`，Cordis 4.1.0、Schemastery 3.19.0 不变。
- 逐包比对 npm 产物：`dsh-host-webserver`、`dsh-scope` 与本插件相关的 lib 构建和类型文件自 rc.1 起逐字节一致；`dsh-client-connection` 只有浏览器包改为压缩输出，导出的 `RpcId` / `apply` / `inject` / `installConnection` / `transportError` 与 rc.1 相同。`0.2.2-rc.2` 与 `0.2.2-rc.3` 的这三包产物同样逐字节一致，所以两项都列入已验证清单。
- 上游升级指南：`0.2.2-rc.1` 之后没有新增版本目录，即 rc.2、rc.3 没有登记的破坏性变更。逐条对照 rc.1 指南，本插件不受影响：不使用 `BundleInfo.updatable`（`plugin-update-method` 不适用）、没有覆盖页头的自定义浮层且目录弹层走原生 `<dialog>`（`window-drag-regions` 不适用），其余条目属账号、CUA、Forge、终端、附件与模型供应商配置。客户端 `settings.section` seat 仍在官方 slot 契约中，本轮唯一变更是可选的 `openSettings(sectionId?)`，本插件未调用。
- **运行时源码不变**：换用 rc.3 依赖重新构建的 `lib/index.js`、`lib/index.d.ts`、`lib/client.js`、`lib/client.js.map` 与 npm 上 `0.7.10` 包内文件逐字节一致。
- 类型检查（含测试工程）、23 个测试文件 / 390 项自动回归、构建、版本一致性与 `npm pack` 内容门禁全部通过。
- 运行 `0.2.2-rc.3` 的实例（profile `web`，装的是 `0.7.10`）只读核对：代理入口 `http 301 → https 200`，手机滚动与轮次浮轨补丁注入正常，客户端模块 `plugins/??dsh-lan-guard/client.js` 返回 200（104160 字节，与本地构建一致），`/plugins/dsh-lan-guard/config` 返回真实配置与监听状态。未做写操作，未改 profile。
- 两版 README 的徽章、已验证行、当前版本句、兼容表、16 个历史验证版本清单与 tag 示例同步为 `0.7.11` / `0.2.2-rc.3`；CHANGELOG 与本发布说明一并更新，npm 实际包内容在发布前后分别核对。
- 2026-11-14 核对 npm 渠道：`next` = `0.2.2-rc.3`，`latest` = `0.2.2-rc.1`，`alpha` = `0.2.2-alpha.3`。

**验证边界**：本次是接口、类型、自动回归与运行实例的只读核对；没有重做 rc.3 的浏览器交互、完整 LAN/WebSocket 或手机实机（触摸、锁屏、语音）验收，alpha.3 的浏览器测量不能当作 rc.3 的实测结果。只修改本插件工作区，不改动 profile、其他工作区插件，也不自动安装或重启 DSH。

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.11
```

安装后重启 DSH 一次。

<h3 id="en-v0.7.11">v0.7.11: DSH 0.2.2-rc.3 compatibility</h3>

Compatible with DeepSeek Harness `0.2.2-rc.3` (and `0.2.2-rc.2`); the supported range `>=0.1.7-rc.1 <0.3.0` is unchanged.

- The compatibility statement gains `0.2.2-rc.2` and `0.2.2-rc.3`. The `<0.3.0` upper bound already covers them, so no range widening or version exemption is needed. Development dependencies `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` move to `0.2.2-rc.3`; Cordis 4.1.0 and Schemastery 3.19.0 stay put.
- Per-package comparison of the npm artifacts: the plugin-facing lib builds and type files of `dsh-host-webserver` and `dsh-scope` are byte-identical from rc.1 onward; `dsh-client-connection` only changed how its browser bundle is minified, and its exports `RpcId` / `apply` / `inject` / `installConnection` / `transportError` are the same as rc.1. The same three packages in `0.2.2-rc.2` and `0.2.2-rc.3` are byte-identical to each other, which is why both are listed as verified.
- Upstream guides: no version directory was added after `0.2.2-rc.1`, so rc.2 and rc.3 carry no registered breaking change. Checked against the rc.1 guides, none applies here: the plugin never reads `BundleInfo.updatable` (`plugin-update-method`), and it owns no overlay above the page header — its directory picker is a native `<dialog>` (`window-drag-regions`). The remaining items cover accounts, CUA, Forge, terminals, attachments and provider credentials. The client `settings.section` seat is still in the official slot contract; the only change this round is the optional `openSettings(sectionId?)`, which the plugin does not call.
- **No runtime source change:** rebuilt against rc.3 dependencies, `lib/index.js`, `lib/index.d.ts`, `lib/client.js` and `lib/client.js.map` are byte-identical to the files inside the published `0.7.10` package.
- Type checks (including the test project), 23 test files / 390 automated cases, the build, the version-consistency gate and the `npm pack` contents gate all pass.
- Read-only checks on the instance running `0.2.2-rc.3` (profile `web`, with `0.7.10` installed): the proxy entry answers `http 301 → https 200`, the mobile scroll and turn-rail patches are injected, the client module `plugins/??dsh-lan-guard/client.js` returns 200 (104160 bytes, matching the local build), and `/plugins/dsh-lan-guard/config` returns the real configuration and listener state. No writes, no profile change.
- Both READMEs update the badge, verified line, current-version sentence, compatibility table, the 16-release verified list and the tag example to `0.7.11` / `0.2.2-rc.3`; the CHANGELOG and these notes are updated with them, and the actual npm package contents were checked before and after publishing.
- Registry channels checked on 2026-11-14: `next` = `0.2.2-rc.3`, `latest` = `0.2.2-rc.1`, `alpha` = `0.2.2-alpha.3`.

**Verification boundary:** this round covers API review, types, automated regression, and read-only checks on a running instance. Browser interaction, full LAN/WebSocket and on-device acceptance (touch, screen locking, dictation) were not repeated for rc.3, and the alpha.3 browser measurements do not count as rc.3 evidence. Changes are confined to this plugin workspace; the profile, other workspaces and the running DSH were left untouched, with no automatic install or restart.

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.11
```

Restart DSH after installation.
