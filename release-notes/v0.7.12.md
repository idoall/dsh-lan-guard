<h3 id="cn-v0.7.12">v0.7.12：兼容 DSH 0.2.2-rc.4</h3>

兼容 DeepSeek Harness `0.2.2-rc.4`（`0.2.2-rc.2` / `0.2.2-rc.3` 同列已验证）；支持范围 `>=0.1.7-rc.1 <0.3.0` 不变。

- 兼容声明新增 `0.2.2-rc.4`；上界 `<0.3.0` 已覆盖，不需要放宽范围或版本豁免。开发依赖 `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` 同步到 `0.2.2-rc.4`，Cordis 4.1.0、Schemastery 3.19.0 不变。
- 逐包比对 npm 产物：`dsh-host-webserver`、`dsh-client-connection`、`dsh-scope` 的 lib 构建与类型在 rc.3 与 rc.4 之间逐字节一致。本插件注入并使用的客户端包也查了：`dsh-client-ui-settings`、`dsh-client-ui-renderer`、`dsh-client-ui-layout` 逐字节一致，`dsh-client-ui-settings-general` 的唯一差异是内嵌的版本文案（`rc.3` → `rc.4`）。`settings.section` slot 契约没有变化。
- 上游升级指南：rc.4 只新增一条 —— `v0.2.2-rc.3/deepseek-refusal-code`，DeepSeek 流式内容拒答的错误码由 `MALFORMED_RESPONSE` 改为 `CONTENT_REFUSED`。本插件不分类 LLM 错误终止块或 `turn/end` 错误码，该条不适用，无需迁移；rc.1 那一批指南（账号、CUA、Forge、终端、附件、插件更新方法、窗口区域）此前已逐条确认不适用。
- **运行时源码不变**：换用 rc.4 依赖重新构建的 `lib/index.js`、`lib/index.d.ts`、`lib/client.js`、`lib/client.js.map` 与 npm 上 `0.7.11` 包内文件逐字节一致。
- 类型检查（含测试工程）、23 个测试文件 / 390 项自动回归、构建、版本一致性与 `npm pack` 内容门禁全部通过。
- 运行 `0.2.2-rc.4` 的实例（profile `web`，装的是 `0.7.11`）只读核对：代理入口 `http 301 → https 200`，手机滚动与轮次浮轨补丁注入正常，客户端模块返回 200 且内容与本地构建同源（仅 sourcemap 尾注被宿主改写），`/plugins/dsh-lan-guard/config` 返回真实配置与监听状态。未做写操作，未改 profile。
- 两版 README 的徽章、已验证行、当前版本句、兼容表、17 个历史验证版本清单与 tag 示例同步为 `0.7.12` / `0.2.2-rc.4`；CHANGELOG 与本发布说明一并更新，npm 实际包内容在发布前后分别核对。
- 2026-11-18 核对 npm 渠道：`next` = `0.2.2-rc.4`，`latest` = `0.2.2-rc.1`，`alpha` = `0.2.2-alpha.3`。

**验证边界**：本次是接口、类型、自动回归与运行实例的只读核对；没有重做 rc.4 的浏览器交互、完整 LAN/WebSocket 或手机实机（触摸、锁屏、语音）验收。只修改本插件工作区，不改动 profile、其他工作区插件，也不自动安装或重启 DSH。

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.12
```

安装后重启 DSH 一次。

<h3 id="en-v0.7.12">v0.7.12: DSH 0.2.2-rc.4 compatibility</h3>

Compatible with DeepSeek Harness `0.2.2-rc.4` (`0.2.2-rc.2` and `0.2.2-rc.3` share the same verification); the supported range `>=0.1.7-rc.1 <0.3.0` is unchanged.

- The compatibility statement gains `0.2.2-rc.4`. The `<0.3.0` upper bound already covers it, so no range widening or version exemption is needed. Development dependencies `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` move to `0.2.2-rc.4`; Cordis 4.1.0 and Schemastery 3.19.0 stay put.
- Per-package comparison of the npm artifacts: `dsh-host-webserver`, `dsh-client-connection` and `dsh-scope` have byte-identical lib builds and types between rc.3 and rc.4. The client packages this plugin injects into and reads were checked as well: `dsh-client-ui-settings`, `dsh-client-ui-renderer` and `dsh-client-ui-layout` are byte-identical, and the only difference in `dsh-client-ui-settings-general` is its embedded version string (`rc.3` → `rc.4`). The `settings.section` slot contract is unchanged.
- Upstream guides: rc.4 adds exactly one — `v0.2.2-rc.3/deepseek-refusal-code`, where DeepSeek's streamed content refusal code changes from `MALFORMED_RESPONSE` to `CONTENT_REFUSED`. This plugin does not classify LLM error blocks or `turn/end` error codes, so the guide does not apply and no migration is needed; the rc.1 batch (accounts, CUA, Forge, terminals, attachments, plugin update method, window regions) was already checked item by item.
- **No runtime source change:** rebuilt against rc.4 dependencies, `lib/index.js`, `lib/index.d.ts`, `lib/client.js` and `lib/client.js.map` are byte-identical to the files inside the published `0.7.11` package.
- Type checks (including the test project), 23 test files / 390 automated cases, the build, the version-consistency gate and the `npm pack` contents gate all pass.
- Read-only checks on the instance running `0.2.2-rc.4` (profile `web`, with `0.7.11` installed): the proxy entry answers `http 301 → https 200`, the mobile scroll and turn-rail patches are injected, the client module returns 200 with content identical to the local build (only the sourcemap trailer is rewritten by the host), and `/plugins/dsh-lan-guard/config` returns the real configuration and listener state. No writes, no profile change.
- Both READMEs update the badge, verified line, current-version sentence, compatibility table, the 17-release verified list and the tag example to `0.7.12` / `0.2.2-rc.4`; the CHANGELOG and these notes are updated with them, and the actual npm package contents were checked before and after publishing.
- Registry channels checked on 2026-11-18: `next` = `0.2.2-rc.4`, `latest` = `0.2.2-rc.1`, `alpha` = `0.2.2-alpha.3`.

**Verification boundary:** this round covers API review, types, automated regression and read-only checks on a running instance. Browser interaction, full LAN/WebSocket and on-device acceptance (touch, screen locking, dictation) were not repeated for rc.4. Changes are confined to this plugin workspace; the profile, other workspaces and the running DSH were left untouched, with no automatic install or restart.

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.12
```

Restart DSH after installation.
