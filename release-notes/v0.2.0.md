<h3 id="cn-v0.2.0">中文</h3>

### 版本对应

仍针对 **DeepSeek Harness `0.1.7-rc.1`**，声明范围不变（`>=0.1.7-rc.1 <0.2.0`）。**DSH 侧没有变化，不需要适配。**

### 为什么必须适配

**不需要适配**。这是一次功能版本：新增「升级检测」，并按用户反馈**移除了右下角的状态胶囊**，同时修掉一处间距叠加。安装形态、配置键、密钥与设备记录格式都没有变化。

### 改了什么

1. **新增：升级检测（SPEC F8）**
   - 设置页显示「当前版本 → npm 上最新版本」，带「检查更新」按钮与 GitHub / 更新日志 / 反馈 Issue 链接；
   - 有新版时展开面板，给出**可复制的升级命令**并提示「需手动重启 dsh 才生效」；
   - **宿主绝不自动安装、绝不重启 dsh**——只报告，操作权在人手里；
   - 只访问**一个**外部端点（`registry.npmjs.org` 的公开版本信息），5 秒超时，结果（含失败）缓存 **6 小时**，「检查更新」可强制刷新；
   - 版本比较**自己实现**（支持 `x.y.z` 与预发布后缀），**未引入任何新依赖**；
   - 离线或注册表不可用时只在界面提示 `检查失败`，**不影响门禁与代理**。
2. **移除：右下角「局域网访问已开启」状态胶囊**（用户反馈）
   - 它把**免密链接（含 `dsh_` token）常驻在屏幕右下角**，截屏或共享屏幕时会一并被拍到；且「不再显示」只在当前标签页会话有效，每次新会话都会重现；
   - 现完全不注册 `shell.overlay`，局域网状态改由设置页「扫码访问」tab 呈现。
3. **修复：设置页芯片行留白过大**——`.lg-root` 的 `gap:18px` 与芯片行的 `margin-bottom:12px` 叠加成 30px，去掉多余 margin 后恢复为 18px，与其它行一致（浏览器实测确认）。

### 谁受影响

- **从 0.1.x 升级的人**：会看到新的升级检测芯片（本版本即最新时显示绿色「✓ 最新」）；
- **不喜欢右下角常驻提示的人**：本版本移除了它（这是有意的行为变化，见上）；
- 使用免密链接的人：链接本身没有任何变化，只是不再常驻在屏幕角落——需要时在设置页「扫码访问」查看；
- 不安装本插件的人：不受影响。

### 兼容性与升级

- 与 DSH `0.1.7-rc.1` 配套；`peerDependencies` 与 `engines` 未变；
- **升级无需任何操作**：配置、密钥、设备配对记录与 CA 全部沿用，不迁移、不失效；
- 回滚到 0.1.1 同样安全（磁盘格式未变）。

### 限制

- 升级检测**不会**替你安装或重启：执行面板里的命令后，需要手动重启一次 dsh；
- 只有确实存在更新的版本时才会出现蓝色面板；离线环境会显示「检查失败」，不影响任何既有功能；
- 其余限制与 0.1.x 相同，逐条列在 README 的「安全边界 / 限制」一节：自签 CA 需每台设备信任一次；mDNS 默认关闭且手机浏览器基本用不上（**二维码才是主路径**）；远程默认只读；局域网明文 HTTP 需显式确认风险；访问密码是共享的；不提供任何公网隧道 / IM Bot / 端口转发。

<h3 id="en-v0.2.0">English</h3>

### Version correspondence

Still built for **DeepSeek Harness `0.1.7-rc.1`** with the same declared range (`>=0.1.7-rc.1 <0.2.0`). **Nothing changed on the DSH side, so no adaptation is needed.**

### Why this release exists

**No adaptation was required.** This is a feature release: it adds update detection, removes the bottom-right status pill after user feedback, and fixes a spacing bug. The install shape, configuration keys, secrets and device-record formats are unchanged.

### What changed

1. **New: update detection (SPEC F8)**
   - The settings page shows the running version next to the newest one on npm, with a "check for updates" button and GitHub / changelog / issue links;
   - When an update exists it expands a panel with a **copyable upgrade command** and a note that a manual dsh restart is required;
   - **The host never installs anything and never restarts dsh** — it only reports; the operator stays in control;
   - It queries exactly **one** external endpoint (public version metadata on `registry.npmjs.org`) with a 5s timeout, caches the result (including failures) for **six hours**, and the button can force a refresh;
   - The version comparison is **implemented in-house** (including prerelease precedence) — **no new dependency**;
   - Being offline or the registry being unreachable is reported in the UI as "check failed" and **never affects the gate or the proxy**.
2. **Removed: the bottom-right "LAN access is on" status pill** (user feedback)
   - It kept the **passwordless link (including the `dsh_` token) permanently on screen**, so screenshots and screen sharing captured it; and its "don't show again" only lasted for the current tab session, so it reappeared every time;
   - The plugin now registers nothing on `shell.overlay`; LAN status lives in the settings page's "QR access" tab.
3. **Fixed: excessive whitespace under the settings chip row** — `.lg-root`'s `gap:18px` stacked with the chip row's `margin-bottom:12px` for 30px; removing the redundant margin restores 18px, matching every other row (confirmed by measurement in a real browser).

### Who is affected

- **Anyone upgrading from 0.1.x** gets the new update chip (green "up to date" while this release is the latest);
- **Anyone who disliked the persistent corner notice**: it is gone (an intentional behaviour change, see above);
- Passwordless-link users: the link itself is unchanged — it is simply no longer parked in the corner; find it in the settings page's "QR access" tab;
- People who do not install this plugin: unaffected.

### Compatibility and upgrading

- Matches DSH `0.1.7-rc.1`; `peerDependencies` and `engines` are unchanged;
- **Upgrading needs no action**: configuration, secrets, paired devices and the CA all carry over — no migration, nothing is invalidated;
- Rolling back to 0.1.1 is equally safe (the on-disk format did not change).

### Limitations

- Update detection **does not** install or restart anything for you: run the command in the panel, then restart dsh once yourself;
- The blue panel only appears when a newer version actually exists; offline environments show "check failed" and nothing else is affected;
- All other limitations are unchanged from 0.1.x and itemised in the README's Security boundary / Limitations section: the self-signed CA must be trusted once per device; mDNS is off by default and phone browsers rarely use it (**the QR code is the reliable path**); remote access is read-only by default; LAN plain HTTP requires an explicit risk acknowledgement; the access password is shared; no public tunnels, IM bots or port forwarding.
