<h3 id="cn-v0.7.13">v0.7.13：兼容 DSH 0.2.2-rc.5</h3>

兼容 DeepSeek Harness `0.2.2-rc.5`（`0.2.2-rc.2` → `rc.4` 同列已验证）；支持范围 `>=0.1.7-rc.1 <0.3.0` 不变。

- 兼容声明新增 `0.2.2-rc.5`；上界 `<0.3.0` 已覆盖，不需要放宽范围或版本豁免。开发依赖 `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` 同步到 `0.2.2-rc.5`，Cordis 4.1.0、Schemastery 3.19.0 不变。
- 逐包比对 npm 产物：`dsh-host-webserver`、`dsh-client-connection`、`dsh-scope` 的 lib 构建与类型在 rc.4 与 rc.5 之间逐字节一致。本插件注入并读取的客户端包也查了：`dsh-client-ui-settings`、`dsh-client-ui-renderer`、`dsh-client-ui-layout` 逐字节一致，`dsh-client-ui-settings-general` 的唯一差异是内嵌的版本文案（`rc.4` → `rc.5`）。`settings.section` slot 契约没有变化。
- 上游升级指南：rc.5 只新增一条 —— `v0.2.2-rc.4/web-search-deepseek-model-default`，交付组合不再固定 `web.searchProvider`，DeepSeek 模型上的网页搜索改走旧版 Messages 搜索（不再按次计费的 Search API）。本插件只做门禁反向代理与局域网接入，既不读写 `web.searchProvider`、也不涉及 `web-search-deepseek`，该条不适用，无需迁移。
- **运行时源码不变**：换用 rc.5 依赖重新构建的 `lib/index.js`、`lib/index.d.ts`、`lib/client.js`、`lib/client.js.map` 与 npm 上 `0.7.12` 包内文件逐字节一致。
- 类型检查（含测试工程）、23 个测试文件 / 390 项自动回归、构建、版本一致性与 `npm pack` 内容门禁全部通过。
- 运行 `0.2.2-rc.5` 的实例（profile `web`，装的是 `0.7.12`）只读核对：代理入口 `http 301 → https 200`，手机滚动与轮次浮轨补丁注入正常，客户端模块返回 200 且内容与本地构建同源（仅 sourcemap 尾注被宿主改写），`/plugins/dsh-lan-guard/config` 返回真实配置与监听状态。未做写操作，未改 profile。
- 两版 README 的徽章、已验证行、当前版本句、兼容表、18 个历史验证版本清单与 tag 示例同步为 `0.7.13` / `0.2.2-rc.5`；CHANGELOG 与本发布说明一并更新，npm 实际包内容在发布前后分别核对。
- 2026-11-21 核对 npm 渠道：`latest` 与 `next` 均为 `0.2.2-rc.5`，`alpha` 为 `0.2.2-alpha.3`。本次验证的 `0.2.2-rc.5` 正是 `latest` 渠道版本，装官方 npm 版 DSH 的用户不再需要切换渠道。

**验证边界**：本次是接口、类型、自动回归与运行实例的只读核对；没有重做 rc.5 的浏览器交互、完整 LAN/WebSocket 或手机实机（触摸、锁屏、语音）验收。只修改本插件工作区，不改动 profile、其他工作区插件，也不自动安装或重启 DSH。

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.13
```

安装后重启 DSH 一次。

<h3 id="en-v0.7.13">v0.7.13: DSH 0.2.2-rc.5 compatibility</h3>

Compatible with DeepSeek Harness `0.2.2-rc.5` (`0.2.2-rc.2` through `rc.4` share the same verification); the supported range `>=0.1.7-rc.1 <0.3.0` is unchanged.

- The compatibility statement gains `0.2.2-rc.5`. The `<0.3.0` upper bound already covers it, so no range widening or version exemption is needed. Development dependencies `dsh-host-webserver` / `dsh-client-connection` / `dsh-scope` move to `0.2.2-rc.5`; Cordis 4.1.0 and Schemastery 3.19.0 stay put.
- Per-package comparison of the npm artifacts: `dsh-host-webserver`, `dsh-client-connection` and `dsh-scope` have byte-identical lib builds and types between rc.4 and rc.5. The client packages this plugin injects into and reads were checked as well: `dsh-client-ui-settings`, `dsh-client-ui-renderer` and `dsh-client-ui-layout` are byte-identical, and the only difference in `dsh-client-ui-settings-general` is its embedded version string (`rc.4` → `rc.5`). The `settings.section` slot contract is unchanged.
- Upstream guides: rc.5 adds exactly one — `v0.2.2-rc.4/web-search-deepseek-model-default`, where the shipped composition stops fixing `web.searchProvider`, so web search on a DeepSeek model runs legacy Messages search instead of the per-request-billed Search API. This plugin is a gated reverse proxy: it neither reads nor writes `web.searchProvider` and never touches `web-search-deepseek`, so the guide does not apply and no migration is needed.
- **No runtime source change:** rebuilt against rc.5 dependencies, `lib/index.js`, `lib/index.d.ts`, `lib/client.js` and `lib/client.js.map` are byte-identical to the files inside the published `0.7.12` package.
- Type checks (including the test project), 23 test files / 390 automated cases, the build, the version-consistency gate and the `npm pack` contents gate all pass.
- Read-only checks on the instance running `0.2.2-rc.5` (profile `web`, with `0.7.12` installed): the proxy entry answers `http 301 → https 200`, the mobile scroll and turn-rail patches are injected, the client module returns 200 with content identical to the local build (only the sourcemap trailer is rewritten by the host), and `/plugins/dsh-lan-guard/config` returns the real configuration and listener state. No writes, no profile change.
- Both READMEs update the badge, verified line, current-version sentence, compatibility table, the 18-release verified list and the tag example to `0.7.13` / `0.2.2-rc.5`; the CHANGELOG and these notes are updated with them, and the actual npm package contents were checked before and after publishing.
- Registry channels checked on 2026-11-21: `latest` and `next` both serve `0.2.2-rc.5`, `alpha` serves `0.2.2-alpha.3`. The verified release is the one the `latest` channel carries, so users installing the official npm DSH no longer need a channel switch.

**Verification boundary:** this round covers API review, types, automated regression and read-only checks on a running instance. Browser interaction, full LAN/WebSocket and on-device acceptance (touch, screen locking, dictation) were not repeated for rc.5. Changes are confined to this plugin workspace; the profile, other workspaces and the running DSH were left untouched, with no automatic install or restart.

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.13
```

Restart DSH after installation.
