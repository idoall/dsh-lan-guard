<h3 id="cn-v0.7.0">📱 手机端轮次浮轨：修掉 iPhone Chrome 错位 + 按住滑动连续预览</h3>

- **修错位**：iPhone Chrome 上卡片刷新后会跑到左上角、文字看不清。根因是两条 WebKit 行为——为读官方预览而调用的 `focus()` 会把右边缘按钮滚进可视区，以及 body 级 `position:fixed` 浮层被算错坐标系。现在卡片直接挂在官方轨道内、预览改用 `pointermove` 触发，`focus()` 已彻底移除。
- **按住后上下滑动 = 连续预览**（对齐 PC 鼠标划过）：手指滑到哪个刻度，卡片立刻换成那一轮的提问与回复摘要；**该刻度同时变成一根满长蓝色条**，一眼能看出当前选中哪一轮（官方原本只给一条 0.9 倍的灰色细线，手指压着看不见）。停在轨道上/下边缘会自动继续卷动；轻点仍是跳转，0.3 秒内快速拖动仍是普通滚动轨道。
- **浮窗内容同步**：连续拖动时 iPhone WebKit 的 React tooltip 提交可能晚于两帧，过去会出现“蓝色跳转按钮已变、标题/摘要却是上一轮”。现在监听官方 tooltip 的真实 DOM 提交，并以有界重读兜底；新刻度尚未提交时先隐藏旧摘要，绝不混轮。
- **修白屏**：DSH 首页没有任何缓存头，浏览器可能复用重启前的文档，而其中的 bundle `?rev=` 已过期（DSH 对过期 rev 返回 404），于是重启后手机白屏、直到清站点数据。代理现在给 HTML 文档补 `cache-control: no-store`（只动文档、不动 bundle）。
- **修「拖动触发上传」**：DSH 的附件视图对任何携带 `Files` 的拖拽都会给出上传落点，因此轨道不能再作为拖拽源（`-webkit-user-drag:none` + 捕获阶段拦掉轨道内的 `dragstart`/`selectstart`）；同时 `pointercancel`（iOS 起原生手势时会走这条路）现在也会吞掉尾随 click，不再让松手后的点击落到附件按钮上。
- **手势不再被浏览器抢走**：`touch-action:none` 原先只写在轨道自身，手指落在刻度（子元素）上时 WebKit 仍会把垂直拖拽判给页面——滑约两格后整页跟着拖、到顶就下拉刷新。现在该规则覆盖**整棵子树**，手势期间用非被动 `touchmove` 直接 `preventDefault()`（多指与轨道外的触摸不受影响），并在移动端关掉 `html/body` 的下拉刷新。
- 全套 **385** 项通过；真实 3081 页面实测：卡片第 16 轮 → 第 38 轮连续切换且不跳转、边缘自动卷动 `scrollTop 182 → 0`、快速拖动 `0 → 50`、轻点仍跳转、0 报错。

<h3 id="en-v0.7.0">📱 The phone turn rail: iOS Chrome misplacement fixed + hold-to-scrub previews</h3>

- **Misplacement fixed**: on iPhone Chrome the card could jump to the top-left corner, unreadable. Two WebKit behaviours caused it — the `focus()` call used to read the official preview could scroll the right-edge button into view, and a body-level `position:fixed` layer could be given the wrong coordinate space. The card now anchors inside the official rail and the preview is triggered by `pointermove`; `focus()` is gone entirely.
- **Hold, then slide up/down = continuous previews** (the desktop hover experience): the card immediately switches to the prompt and reply excerpt of whatever tick the finger is over, and **that tick turns into a full-length blue bar** so the current selection is obvious (the official hover style is a 0.9-scale grey hairline, invisible under a finger). Resting at either rail edge keeps auto-scrolling; a tap still jumps, and a quick drag within 0.3s still scrolls the rail normally.
- **Card-content synchronization**: on iPhone WebKit React can commit the official tooltip later than two frames, which previously left a new blue jump label beside the old title/excerpt. The card now observes the official tooltip DOM plus a bounded retry; while the new tooltip is pending it hides the old excerpt rather than mixing turns.
- **Blank-page fix**: DSH ships no cache headers on its index, so a browser may reuse the document rendered before a restart — and its `?rev=` bundle URLs are then stale, which DSH answers with 404, leaving a blank page on mobile until site data is cleared. The proxy now adds `cache-control: no-store` to HTML documents only.
- **Drag-triggered-upload fix**: DSH's attachment view offers a drop target for any drag carrying `Files`, so the rail must never be a drag source (`-webkit-user-drag:none` plus capture-phase `dragstart`/`selectstart` refusal inside the rail); and `pointercancel` — the path iOS takes when it grabs a native gesture — now swallows the trailing click too, so it cannot land on the attach control.
- **The gesture can no longer be hijacked**: `touch-action:none` used only to sit on the rail itself, so with the finger on a tick (a descendant) WebKit still handed the vertical drag to the page — after roughly two ticks the whole page dragged and reaching the top fired pull-to-refresh. The rule now covers the entire subtree, a non-passive `touchmove` refuses the page outright for the duration of the gesture (multi-finger and off-rail touches untouched), and pull-to-refresh is disabled on the phone.
- All **385** specs pass. Measured on the real 3081 page: card swept turn 16 → turn 38 with no navigation, edge auto-scroll `scrollTop 182 → 0`, quick drag `0 → 50`, tap still jumps, zero errors.
