<h3 id="cn-v0.7.0">📱 手机端轮次浮轨：修掉 iPhone Chrome 错位 + 按住滑动连续预览</h3>

- **修错位**：iPhone Chrome 上卡片刷新后会跑到左上角、文字看不清。根因是两条 WebKit 行为——为读官方预览而调用的 `focus()` 会把右边缘按钮滚进可视区，以及 body 级 `position:fixed` 浮层被算错坐标系。现在卡片直接挂在官方轨道内、预览改用 `pointermove` 触发，`focus()` 已彻底移除。
- **按住后上下滑动 = 连续预览**（对齐 PC 鼠标划过）：手指滑到哪个刻度，卡片立刻换成那一轮的提问与回复摘要；停在轨道上/下边缘会自动继续卷动。轻点仍是跳转，0.3 秒内快速拖动仍是普通滚动轨道。
- 全套 **376** 项通过；真实 3081 页面实测：卡片第 16 轮 → 第 38 轮连续切换且不跳转、边缘自动卷动 `scrollTop 182 → 0`、快速拖动 `0 → 50`、轻点仍跳转、0 报错。

<h3>升级</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

重启 dsh 一次；`mobileTurnRail` 在 **设置 → 局域网访问 → 连接与证书 → 手机端轮次导航**（默认关闭）。打开后刷新页面生效。

<h3 id="en-v0.7.0">📱 The phone turn rail: iOS Chrome misplacement fixed + hold-to-scrub previews</h3>

- **Misplacement fixed**: on iPhone Chrome the card could jump to the top-left corner, unreadable. Two WebKit behaviours caused it — the `focus()` call used to read the official preview could scroll the right-edge button into view, and a body-level `position:fixed` layer could be given the wrong coordinate space. The card now anchors inside the official rail and the preview is triggered by `pointermove`; `focus()` is gone entirely.
- **Hold, then slide up/down = continuous previews** (the desktop hover experience): the card immediately switches to the prompt and reply excerpt of whatever tick the finger is over, and resting at either rail edge keeps auto-scrolling. A tap still jumps, and a quick drag within 0.3s still scrolls the rail normally.
- All **376** specs pass. Measured on the real 3081 page: card swept turn 16 → turn 38 with no navigation, edge auto-scroll `scrollTop 182 → 0`, quick drag `0 → 50`, tap still jumps, zero errors.

<h3>Upgrade</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

Restart dsh once; `mobileTurnRail` lives under **Settings → 局域网访问 → 连接与证书 → 手机端轮次导航** (off by default) and applies on the next page load.
