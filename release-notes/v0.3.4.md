<h3 id="cn-v0.3.4">中文</h3>

### 问题：局域网访问时，官方设置页报「settings are unavailable in this browser」

**症状**：在局域网另一台机器（含手机）打开「设置 → 模型」，报 `加载提供商目录失败: settings are unavailable in this browser`；同一台电脑用 `127.0.0.1` 打开则完全正常。

**原因**（**不是本插件的故障**）：DSH 客户端按**页面地址栏**是否为回环决定官方设置面能否持久化 —— 非回环页面被永久降级为「内存态」，于是模型页拿不到设置数据。代理改写请求头解决不了，因为这个判断发生在**访客自己的浏览器里**，读的是地址栏而不是请求头。

### 新增：局域网设备可用官方设置页（默认开启）

**设置 → 局域网访问 → 连接与证书** 新增开关「**局域网设备可用官方设置页**」，默认**开启**。开启时，插件在宿主侧往 index.html 的 `<head>` 后注入一行脚本，把 DSH 桌面壳自己使用的「本机界面」标记交给页面：

```html
<script>/*dsh-lan-guard:settings-unlock*/(function(){var t=globalThis.__DSH_TRANSPORT__;globalThis.__DSH_TRANSPORT__=Object.assign({},t!==null&&typeof t==="object"?t:{},{ownsHost:true});})()</script>
```

**刷新页面即生效，无需重启 dsh**；把开关关掉即恢复 DSH 原生行为（非本机访问重新显示「不可用」）。

### 边界：这是界面解锁，不是新增权限

- 经代理的请求本就被改写成回环 `host`，DSH 的设置接口**只由本插件的门禁与管理员策略把关**（读取仍由 DSH 脱敏）；该开关只是让官方页面不再假装「不可用」；
- 注入**只作用于 index.html**，且早于压缩，不缓冲、不改写代理响应，**不碰代理转发热路径**；
- 采用**合并**而非覆盖 `__DSH_TRANSPORT__`，保留上游将来写入的值；
- 依赖 DSH 内部全局名：上游若改名，此开关**静默失效**（退回原来的报错，不会崩）。

### 验证

- `pnpm run typecheck` ✓；`pnpm test` — **263 项全绿**（0.3.3 为 247 项，+16）；
- 注入脚本在真实 Chrome、经**非回环地址**（`http://10.0.0.30:3998`）实测三种情况：无预置全局、预置对象（`streamBaseUrl` 保留且标记翻真）、预置字符串（不抛错），结果均为「本机界面」标记为真；
- **未验证**：真实 DSH 页面上官方「模型」页的最终可用性 —— 需要把本版本装进运行中的 profile 并重启 dsh，属发布后的单独步骤。

### 升级

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

然后重启一次 DSH。插件不会自己安装或重启任何东西 —— 命令由你执行。

<h3 id="en-v0.3.4">English</h3>

### The problem: the official settings page reported "settings are unavailable in this browser" over the LAN

**Symptom**: on another machine on the LAN (phones included), **Settings → Models** reported `加载提供商目录失败: settings are unavailable in this browser`, while the very same page opened on the host at `127.0.0.1` worked fine.

**Cause** (**not a failure of this plugin**): DSH decides whether its official settings surface may persist anything from the **page's own address bar**. A non-loopback page is permanently downgraded to an in-memory state, so the models page never receives its settings data. Rewriting request headers cannot help: the decision is made inside the **visitor's own browser** and reads the address bar, not a header.

### New: the official settings page on the LAN (on by default)

**Settings → 局域网访问 → 连接与证书** gains an "**official settings page on the LAN**" switch, **on by default**. When it is on, the plugin injects one line into the served index — the same "this is the host's own surface" marker DSH's desktop shell sets:

```html
<script>/*dsh-lan-guard:settings-unlock*/(function(){var t=globalThis.__DSH_TRANSPORT__;globalThis.__DSH_TRANSPORT__=Object.assign({},t!==null&&typeof t==="object"?t:{},{ownsHost:true});})()</script>
```

**Refresh the page to apply; no dsh restart.** Turning the switch off restores DSH's stock behaviour (non-loopback visitors see "unavailable" again).

### Boundary: this is a UI unlock, not a new privilege

- A proxied request is already rewritten to a loopback `host`, and DSH's settings RPC is gated **only by this plugin's visitor gate and admin policy** (reads are still redacted by DSH). The switch merely stops the official page from pretending the surface does not exist;
- the injection touches **index.html only** and runs before compression, so it never buffers or rewrites a proxied response and **never enters the proxy's forwarding hot path**;
- it **merges** into `__DSH_TRANSPORT__` instead of replacing it, preserving any value a future DSH release puts there;
- it depends on a DSH-internal global name: if upstream renames it, the switch **fails silently** back to the original error — it never breaks the page.

### Verification

- `pnpm run typecheck` passes; `pnpm test` — **263 passing** (247 in 0.3.3, +16);
- the injected script was exercised in a real Chrome over a **non-loopback address** (`http://10.0.0.30:3998`) in three states: no pre-existing global, a pre-existing object (`streamBaseUrl` preserved, marker flipped to true) and a pre-existing string (no throw) — all three end with the marker true;
- **not verified**: the final usability of the official Models page on a live DSH — that needs this build installed into a running profile and a dsh restart, which is a separate post-release step.

### Upgrade

```sh
dsh plugin --profile web add dsh-lan-guard@latest
```

Then restart DSH once. The plugin never installs or restarts anything by itself — you run the command.
